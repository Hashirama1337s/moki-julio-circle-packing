## 0. Claim

**Theorem.** Let h = 4/5, N = 4 (resp. h = 3/5, N = 6). No N circles of equal radius r > r* fit, without overlapping, in a
1 × h rectangle, where r* = 7/20 − √2/10 (resp. 1/5 − √2/30). The configuration c* of §2 attains r*.

**Corollary (same data).** Every packing of radius r* is an image of c* under the rectangle's four mirror symmetries
and relabelling. §5.5 gives the proof.

## 1. One frame

**The frame is the centred frame, and all statements are made in it.** The rectangle is [−1/2, 1/2] × [−h/2, h/2]. The
centres are c = (x_0, y_0, …, x_{N−1}, y_{N−1}), labelled 0 … N−1 as in the files. The constraints are, in this fixed
order:

- walls, for each circle i: L: x_i + 1/2 − r ≥ 0, R: 1/2 − x_i − r ≥ 0, B: y_i + h/2 − r ≥ 0, T: h/2 − y_i − r ≥ 0;
- pairs, for i < j: g_ij = |c_i − c_j|² − 4r² ≥ 0.

F(r) is the set of configurations that satisfy all of them. F(r′) ⊆ F(r) for r′ ≥ r > 0 (nesting). F(r) is invariant
under the group Γ generated by relabelling and the mirrors (x, y) ↦ (s_x x, s_y y), s ∈ {±1}². Γ acts by
‖·‖_∞-isometries.

**The cut set D** (non-strict): x_0 ≤ x_1 ≤ … ≤ x_{N−1}, x_0 + x_{N−1} ≤ 0, y_0 ≤ 0.

*Lemma S (the cuts lose no orbit).* Every c has an image γc ∈ D with γ ∈ Γ. *Proof.* Sort by x, breaking ties
arbitrarily. If x_0 + x_{N−1} > 0, mirror in x and re-sort. The new extremes are −x_{N−1} and −x_0, whose sum is < 0.
Then, if y_0 > 0 for the point now labelled 0, mirror in y. This leaves every x, so the order and the sum, unchanged.
Ties are handled because any tie order is allowed at the first step. ∎

**The engine's chart** (a fixed affine map, used only inside Lemma 2). For a rational r_t, the code works in the *point
frame* p = c + (1/2 − r_t, h/2 − r_t) ∈ [0, W] × [0, H], with W = 1 − 2r_t, H = h − 2r_t and d = 2r_t. It uses
grid integers X = G·p_x/W and Y = G·p_y/H. A box [X0, X1, Y0, Y1] of point i is the closed real box
[X0·W/G, X1·W/G] × [Y0·H/G, Y1·H/G]. In this chart F(r_t) is exactly {X, Y ∈ [0, G]; |p_i − p_j| ≥ d}: the walls are the
root box, not a test. The cuts become, with the code's constants (`Engine.apply_symmetry`):

| centred frame | code (grid) | note |
|---|---|---|
| x_i ≤ x_{i+1} | X_i ≤ X_{i+1} | the chart is increasing |
| x_0 + x_{N−1} ≤ 0 | X_0 + X_{N−1} ≤ G | p_0 + p_{N−1} = x_0 + x_{N−1} + W |
| y_0 ≤ 0 | Y_0 ≤ `half` = G // 2 | exact because G is a power of two ≥ 2 (checked; see §5.2 finding 2) |

The earlier draft's "x_1 + x_N ≤ W, y_1 ≤ H/2" were these cuts in the point frame (1-based labels). The frame was not
named. It is now pinned.

## 3. Lemma 1 (local ball)

Let T be the tight set, λ ∈ Q(√2)^T with every λ_k > 0, Σ_T λ_k ∇_c g_k(c*) = 0, and (normalisation) Σ λ_k w_k = 1, where
w_k = −∂g_k/∂r (1 for walls, 8r* for pairs). Let Λ = Σ_{pairs} λ_k. Let B ⊆ T have |B| = 2N, and let M be the 2N × 2N
matrix of rows ∇_c g_k(c*), k ∈ B, with an inverse M⁻¹. Put η = min_B λ_k / (2‖M⁻¹‖_∞) and ρ₀ = η/(16Λ). **Then every
c ∈ F(r*) with ‖c − c*‖_∞ ≤ ρ₀ equals c*.** The same holds with c* replaced by γc* for any γ ∈ Γ, with the same ρ₀.

*Pullback.* In the centred frame, Γ acts linearly by coordinate permutations and sign changes. Each γ is therefore a
‖·‖_∞-isometry, and γF(r*) = F(r*). Let c ∈ F(r*) with ‖c − γc*‖_∞ ≤ ρ₀. Then γ⁻¹c ∈ F(r*) and
‖γ⁻¹c − c*‖_∞ = ‖γ⁻¹(c − γc*)‖_∞ ≤ ρ₀. So γ⁻¹c = c* by the lemma, i.e. c = γc*. Every group copy γc* inherits the same
ρ₀, with no new computation.

*Proof.* Write d = c − c*. The constraints are affine (walls) or quadratic (pairs), so exactly
g_k(c* + d) = ∇g_k·d + q_k(d), with q_k = |d_i − d_j|² for pair ij and 0 for walls, using g_k(c*) = 0 on T.
c ∈ F(r*) gives −∇g_k·d ≤ q_k(d). Equilibrium gives Σ λ_k ∇g_k·d = 0. So φ(d) := Σ λ_k max(0, −∇g_k·d) = ½ Σ λ_k |∇g_k·d|.
*Upper:* φ(d) ≤ Σ λ_k q_k(d) ≤ 8Λ‖d‖²_∞, since d_i − d_j has two components, each of absolute value ≤ 2‖d‖_∞.
*Lower:* drop the non-negative terms outside B. Then φ(d) ≥ ½ min_B λ_k ‖Md‖_1 ≥ ½ min_B λ_k ‖Md‖_∞
≥ ½ min_B λ_k ‖d‖_∞ / ‖M⁻¹‖_∞ = η‖d‖_∞. Hence d = 0 or ‖d‖_∞ ≥ η/(8Λ) = 2ρ₀. ∎

*Remarks.* (i) Stresses are not unique: the family has 1 parameter (N = 4) and 2 parameters (N = 6). The lemma needs one
strictly positive stress. We fix the free parameters at 18463/420739 (N = 4) and 32325/996184, 18551/391467 (N = 6).
A float LP chose these values, and they are then verified exactly. (ii) No non-zero μ ≥ 0 has Σ μ_k w_k = 0, because
every w_k > 0. (iii) The normalisation is not used in the proof. It is checked anyway.

**Rigour (all in the certificate, re-verified by the replay).** λ is given exactly in Q(√2). Equilibrium (2N
coordinates) and normalisation are checked by exact field arithmetic. For each k a rational λ_lo,k > 0 is given, with
λ_k − λ_lo,k ≥ 0 by the exact sign test. Λ_hi is rational with Λ_hi − Λ ≥ 0 exactly. **M and M⁻¹ are matrices over
Q(√2).** M is recomputed from c* and B. M·M⁻¹ = I and M⁻¹·M = I are checked entry by entry in the field, so M⁻¹ is not
taken on trust from any algebra system (none is used). normMinv_hi is rational, and for every row a,
normMinv_hi − Σ_b |M⁻¹_ab| ≥ 0 exactly (|·| exact via the sign test). The certificate's ρ is the rational

  ρ = min_{k∈B} λ_lo,k / (2·normMinv_hi) / (16·Λ_hi) ≤ ρ₀.

The replay checks this formula as an equality of rationals.

## 4. r_t and the snap, from one √2 enclosure

S2_LO = ⌊√2·10⁵⁰⌋/10⁵⁰, computed with the integer square root (no floats), and S2_HI = S2_LO + 10⁻⁵⁰.
S2_LO² < 2 < S2_HI² is checked on rationals, so S2_LO < √2 < S2_HI.

- **r_t.** r* = p − q√2 with q > 0 (q = 1/10, 1/30) is decreasing in √2. So r_t := p − q·S2_HI − 10⁻⁴⁰ satisfies
  r_t < p − q√2 = r*. This is proved, not printed. The replay also checks r* − r_t > 0 with the exact sign test, and
  r_t > 0.
- **Snap.** The engine compares rationals, so each image coordinate s·(a + b√2) + shift of γc* in the point frame is
  replaced by s·(a + b·S2_LO) + shift. The shift is 1/2 − r_t or h/2 − r_t, which is rational. The error is
  |b|·|√2 − S2_LO| < |b|·(S2_HI − S2_LO). So ‖c_snap − γc*‖_∞ < snap_err_hi := max|b|·10⁻⁵⁰ (3·10⁻⁵¹ and 1.7·10⁻⁵¹).
  The replay also checks each coordinate's error exactly in Q(√2).
- **ρ′** := ⌊ρ − snap_err_hi⌋ on the grid 10⁻³⁰. So ρ′ + snap_err_hi ≤ ρ, an exact rational inequality that the
  replay checks.

## 5. Lemma 2 (global): written against the code

### 5.1 The integer tests in `prove_small.Engine`

Write W = Wn/Wd, H = Hn/Hd and d = dn/dd in lowest terms, with positive denominators. Put A′ = Wn²·Hd²·dd²,
B′ = Hn²·Wd²·dd², C′ = dn²·Wd²·Hd² and g = gcd(A′, B′, C′) ≥ 1. The code's integers are A = A′/g, B = B′/g and
CG = (C′/g)·G². `dist2_lt(dx, dy)` is A·dx² + B·dy² < CG.

*Equivalence.* Let K := Wd²·Hd²·dd²·G²/g. K is a **positive rational**: every factor is a positive integer (G ≥ 2,
g ≥ 1). It need not be an integer, and the argument does not need one. Multiplying the real inequality
(dx·W/G)² + (dy·H/G)² < d² by K gives exactly A·dx² + B·dy² < CG. Multiplying by K > 0 preserves a strict inequality
in both directions, so the two are equivalent. **Positivity of K is the only property used.**
`exact_prove.LoggedEngine.__init__` computes these integers for the chosen G exactly as `Engine.__init__` does. The
replay does not use them: it forms its own common denominator L of (W/G)², (H/G)² and d², and tests
fx²·(W/G)²L + fy²·(H/G)²L < d²L. L > 0 is again the only property used.

- `far(a0, a1, b0, b1) = max(a1 − b0, b1 − a0)`. For non-empty intervals this is max{|u − v| : u ∈ [a0, a1],
  v ∈ [b0, b1]}, attained at end points.
- `too_close(P, Q) = dist2_lt(far_x, far_y)`. The two coordinates separate, so this says **the range maximum of
  |p − q|² over P × Q (a corner) is < d²**. Equivalently, the pair constraint g = |p − q|² − d² has range maximum < 0.
- `point_forbidden(p, Q)` means max_{q∈Q} |p − q|² < d², by the same end-point formula.
  `rect_forbidden(R, Q)` asks this at the four corners of R. The map p ↦ max_q |p − q|² is convex, so its maximum over
  R is at a corner. So `rect_forbidden(R, Q)` is the same predicate as `too_close(R, Q)`.

### 5.2 Exclusion lemma (every discard and every removal in the code is an instance)

Let S = S_0 × … × S_{N−1} be a node (closed grid boxes). Write F_t for F(r_t) in the chart.

- **(E1) pair.** If R ⊆ S_i is a closed box, j ≠ i, and `too_close(R, S_j)`, then no c ∈ S ∩ F_t has p_i ∈ R, because
  every such pair violates |p_i − p_j| ≥ d. With R = S_i we get S ∩ F_t = ∅. Code: the pair test in `tighten` and in
  `build_starts` (witness `pair`); the final test in `shrink_box` and a covering hole in `best_hole` (witness `forbid`,
  the same predicate).
- **(E2) cuts.** If some interval of S is empty, or lo(X_i) > hi(X_{i+1}), or lo(X_0) + lo(X_{N−1}) > G, then
  S ∩ D = ∅. Code: the `return False` exits of `apply_symmetry` and `x_impossible` (witnesses `empty`, `xorder`,
  `xsum`).
- **Walls** are not a test. They are the root box [0, G]^{2N}.

**Reductions** (S → S′ with D ∩ F_t ∩ S ⊆ S′):
(R1) the clips of `apply_symmetry`: hi(X_i) ← min(hi(X_i), hi(X_{i+1})); lo(X_{i+1}) ← max(lo(X_{i+1}), lo(X_i));
hi(X_0) ← min(·, G − lo(X_{N−1})); hi(X_{N−1}) ← min(·, G − lo(X_0)); hi(Y_0) ← min(·, G/2). Each follows from one
non-strict cut.
(R2) `push_low_x/push_high_x/push_low_y/push_high_y` in `shrink_box`: a boundary strip R of S_i with
`rect_forbidden(R, S_j)` is removed by (E1). The binary search keeps the invariant that the returned end's strip is
forbidden. If the first test fails, the bound is unchanged. The new box keeps the strip's inner boundary line, which is
conservative.

**Splits** (D ∩ F_t ∩ S ⊆ ∪ children):
(S1) `hole_children`: a hole R ⊆ S_i with positive width and height and `rect_forbidden(R, S_j)`. The children replace
S_i by the up-to-four closed parts [x0, hx0] × [y0, y1], [hx1, x1] × [y0, y1], [hx0, hx1] × [y0, hy0] and
[hx0, hx1] × [hy1, y1]. Any point of S_i outside R lies in one of them, by case analysis on x then y. The filter
`bulk < parent` never drops a part: each part is strictly shorter than S_i in one direction.
(S2) `bisect`: closed halves [lo, mid], [mid, hi], with mid = ⌊(lo + hi)/2⌋.
(S0) the start (`build_starts`): the cells of `make_cells` are products of closed intervals from `axis_bounds` that
cover [0, G], with neighbours sharing end points. Every cell has `too_close(cell, cell)`, i.e. diameter < d. So a
feasible configuration has its points in pairwise distinct cells, and some injective assignment of cells to points
contains it. All injective assignments are enumerated (`permutations`). Rejections are by (E2) `xorder` or (E1) `pair`.

**Findings on the code (stated plainly).**
1. No discard or removal test in `prove_small.Engine` is unsound as exact arithmetic. Every decision is an integer
   comparison equivalent to one of (E1), (E2), (R1), (R2), (S0)–(S2) above. The heuristics decide only *what to try*,
   never *what to drop*: `can_forbid` gating, `deepest_seed`/`grow_hole`, `choose_bisect`, `score` ordering, and the
   64-round cap in `tighten` (which returns a non-fixpoint box, still a superset).
2. `apply_symmetry` uses `half = G // 2` for the cut Y_0 ≤ G/2. This is exact only for even G. With G odd it would cut
   away Y_0 ∈ (⌊G/2⌋, G/2], an unsound cut. It never bit: `choose_g` gives powers of two ≥ 4096, and the runs use
   G = 8192 and 32768. But the earlier `exact_prove.py` started its doubling at G = 1. **Fixed:** the grid now starts at
   2, `LoggedEngine` refuses odd G, and the replay requires G even.
3. `Engine.branch` returns `None` both for "a hole covers S_i" (a sound discard) and for "the chosen side has length < 2"
   (bisect impossible). The second would silently drop a live node. It is unreachable in both search loops, because
   `max_side ≤ 1` is caught as UNDECIDED before `branch`, and `choose_bisect` falls back to the longest side. But it is a
   trap. **Fixed in the copy:** `LoggedEngine.branch_log` separates the two cases and reports the second as UNDECIDED.
   The replay accepts a discard only with a witness.
4. The earlier `exact_prove.py` printed "PROVED (start)" if no start assignment survived. Since c* is feasible at r_t,
   that can only mean a bug. **Fixed:** it is now an error.
5. The earlier `exact_prove.py` used float evaluation (`sp.N(g, 40) > −1e−30`) as its feasibility test, and 44-digit
   floors for r_t and the images. **Replaced** by exact sign tests and the §4 enclosure.

`exact_prove.LoggedEngine` re-implements `build_starts`, `apply_symmetry`, `shrink_box`, `tighten`, `best_hole` and
`branch` with a witness log. **On every node** it asserts that its result equals the unmodified `Engine` method's. So
the tree files are the run of Grok's engine, not of a re-implementation.

### 5.3 Covering lemma and COMPLETE

Root = [0, G]^{2N} (the walls at r_t). Every node carries a box S. Its fate is one of: *split* (the listed children,
with the reduction steps first), *discarded* (the reduction steps, then a witness), or *accepted* (the reduction steps,
then §5.4). By (R1), (R2), (S0)–(S2), (E1) and (E2): **D ∩ F_t ∩ S ⊆ ∪ (children's boxes)** for a split, and
**= ∅** for a discard.

**COMPLETE** means that the log is a finite rooted tree in which every node has one of these three fates, every split's
children are exactly the boxes the split produces, every discard carries a witness that holds, and no leaf is
undecided. By induction over the tree, COMPLETE gives **D ∩ F_t ⊆ ∪ {tightened boxes of the accepted leaves}**.

| case | start (cells; assignments) | nodes processed | splits | leaves | accepted | discarded (witnesses) | undecided |
|---|---|---|---|---|---|---|---|
| N = 4 | 2×2 cells; 24 kept, 0 rejected | 28 | 2 bisect | 26 | 1 | 25 (24 pair, 1 empty) | 0 |
| N = 6 | 3×2 cells; 288 kept, 432 rejected (xorder) | 296 | 4 bisect | 292 | 1 | 291 (120 pair, 171 empty) | 0 |

The replay reports **29 and 297 tree records**. These are the 28 and 296 processed nodes above plus the root record. The
kept start assignments (24; 288) are among the processed nodes. The rejected ones (0; 432) are logged, with witnesses,
inside the root record and are not separate nodes.

### 5.4 Acceptance predicate (exact)

A tightened node S is ACCEPTED if there are a mirror s ∈ {±1}² and a permutation π with, for every i:
[X0_i·W/G, X1_i·W/G] ⊆ [X^s_{π(i)} − ρ′, X^s_{π(i)} + ρ′] and [Y0_i·H/G, Y1_i·H/G] ⊆ [Y^s_{π(i)} − ρ′, Y^s_{π(i)} + ρ′].
Here (X^s_k, Y^s_k) = (s_x(a + b·S2_LO) + 1/2 − r_t, s_y(a′ + b′·S2_LO) + h/2 − r_t) is the snapped point-frame image
of c*_k. These are comparisons of rationals. Then every c in S has ‖c − γc*‖_∞ ≤ ρ′ + snap_err_hi ≤ ρ ≤ ρ₀, where
γ ∈ Γ is (s, π): the configuration whose i-th centre is (s_x x*_{π(i)}, s_y y*_{π(i)}).

### 5.5 Proof of the Theorem and the Corollary

Suppose c ∈ F(r) with r > r*. By Lemma S some γc ∈ D, and γc ∈ F(r) ⊆ F(r*) ⊆ F(r_t) by nesting (0 < r_t < r*). In the
chart γc ∈ D ∩ F_t. By §5.3 it lies in an accepted leaf, so by §5.4 ‖γc − γ′c*‖_∞ ≤ ρ for some γ′ ∈ Γ. By Lemma 1
(γc ∈ F(r*)), γc = γ′c*. But γ′c* ∉ F(r) for r > r*, since its tight wall constraints become negative. Contradiction.
So F(r) = ∅ for r > r*, and c* ∈ F(r*) (§2). The same chain, started from c ∈ F(r*), gives γc = γ′c*: the Corollary. ∎

rectangle, with children ids), discarded (witness `pair i j fx fy` | `forbid i j` | `empty i axis` | `xorder i` |
`xsum`), or accepted (mirror, permutation). The root lists the cells, the surviving assignments and a witness for every
rejected assignment.

`proofs/exact/replay_exact.py` uses only the standard library and imports neither `exact_prove.py` nor `prove_small.py`.
Its arithmetic is independent: tuples over `Fraction` for Q(√2), and its own common-denominator pair test. It
re-verifies:
- all of §2 to §4 from the certificate: the enclosure, c* ∈ F(r*), T as the exact zero set, equilibrium, normalisation,
  0 < slack_lo ≤ slack for every non-tight constraint, λ ≥ λ_lo > 0, Λ_hi, M from c*, M·M⁻¹ = M⁻¹·M = I, the norm
  bound, the ρ formula, r_t's formula and r_t < r*, the snapped images, and ρ′ + snap_err_hi ≤ ρ;
- all of §5 from the tree: root = [0, G]^{2N}; G even; W, H and d recomputed from h and r_t; the cells form a product
  cover of [0, G]² with every diameter < d, and every injective assignment is accounted for; every reduction step (only
  the non-strict cuts exist as operations); every strip, hole and discard witness by the range-maximum test; every split
  reproduced and matched to its children's boxes; every acceptance by the exact subset test; a finite tree with no
  undecided leaf;
- a positive control: every representative of c* in D (exact, in Q(√2)) lies in an accepted leaf.

**Mutation test (shipped): `proofs/exact/mutate_check.py`.** It uses the standard library only, runs from any working
directory, and writes only to a temporary directory. It applies 34 corruptions per case, 68 in all, one at a time. It
re-binds the tree to an edited certificate, so that the corruption itself must be caught, except in the one mutation
that tests the binding.

- Certificate corruptions: λ + 10⁻⁶⁰; λ_lo above λ; Λ_hi below Λ; ρ above its formula; ρ′ = ρ; r_t above r*;
  M⁻¹ + 10⁻⁷⁰; normMinv_hi too small; a repeated basis row; c* moved by 10⁻⁶⁰; a contact dropped from T; a slack_lo
  above the slack; an image moved by 10⁻⁴⁵; S2_HI below √2; the certificate edited without re-binding.
- Tree corruptions: G + 1; a cell removed; a gap in the cover; an oversized cell; a kept start deleted; a kept start
  relabelled as rejected with a false witness; false pair and empty witnesses; a strip pushed one grid step too far; a
  non-existent cut operation; an out-of-range order clip; a wrong permutation or mirror in an acceptance; a dropped
  child; a shifted bisection; a leaf marked undecided; an edited box or tightened box; an orphan node.

Result: **68/68 corruptions rejected; the unmodified files PASS on both cases.**

**Negative controls** (`python proofs/exact/exact_prove.py <case> 1/1000`, r_t = (p − q·S2_HI)(1 − 10⁻³)): both runs end
UNDECIDED, because feasible configurations reach outside the balls. They write no files.

## 7. What this does not claim / trust base

- Lemma 1, Lemma S, the exclusion and covering lemmas, and the proof of §5.5 are hand proofs. The machine checks the
  finite data they quantify over.
- Trusted: Python's `int`, `fractions.Fraction`, `json` and `gzip`. The prover and the checker were written by the same
  team. They are independent at the code level (no shared imports, different arithmetic code, a different formulation of
  the pair test), not at the author level. A reviewer-written checker for the same JSON would remove that.
- The claim concerns these two (N, h) only.
